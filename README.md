# Оформление билетов — зал «Лен»

Учебная касса на моковых данных: от выбора сеанса до результата. Оплаты нет, письма не уходят, заказы живут в памяти процесса FastAPI до перезапуска.

## Запуск

Нужны Python 3.11+ и Node.js 18.18+ (Node только собирает интерфейс на React).

Терминал 1, касса:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r backend/requirements.txt
pytest backend/tests
uvicorn app.main:app --app-dir backend --reload --port 8000
```

Терминал 2, интерфейс:

```bash
cd frontend
npm install
npm run dev
```

Открыть [http://localhost:5173](http://localhost:5173). Запросы `/api` проксируются на кассу. Если порт 8000 занят, поднимите uvicorn на другом и запустите интерфейс так: `TICKET_API=http://127.0.0.1:8001 npm run dev`.

Остановка — `Ctrl+C` в обоих терминалах. Пока процесс кассы жив, остаток основного зала общий для всех вкладок. Кнопка «Вернуть места и начать заново» сбрасывает его без перезапуска.

## Два исхода

**Заказ оформлен.** Основной зал, 19:30. Например: Анна, 34 года и Лев, 8 лет, один email. На проверке видно состав и 3 000 ₽. «Изменить данные» возвращает к анкете. «Подтвердить заказ» списывает места и показывает билет с номерами мест.

**Места закончились до подтверждения.** Поздний сеанс, 21:30. На афише 3 места. На шаге проверки касса показывает, что они уже разобраны (было 3, сейчас 0). Подтверждение получает отказ, заказ не создаётся. Тот же состав можно сразу провести через основной зал.

Основной зал тоже умеет отказать по-настоящему: в нём 8 мест. Когда их меньше, чем участников, подтверждение отклоняется.

## Правила

Цены и пороги на сервере — в `backend/app/rules.py`. Форма повторяет их в `frontend/src/lib/rules.ts`, чтобы подсказки появлялись сразу. Решает касса.

- В заказе от 1 до 4 участников.
- Младше 14 лет — детский билет, 1 000 ₽. С 14 лет — полный, 2 000 ₽.
- Ребёнок младше 14 лет проходит только вместе с участником от 18 лет в этом же заказе.
- Участник 14–17 лет платит полную цену и не считается сопровождающим.
- Каждому участнику нужны имя и возраст. Email один на заказ.
- Состав и сумма видны до подтверждения, данные можно изменить.
- Места не держатся, пока заказ не подтверждён. Номера мест появляются только в успешном билете.

## Как устроено

FastAPI держит кассу. React и TypeScript рисуют шаги. Tailwind отвечает за вёрстку.

- `GET /api/event` — сколько мест в основном зале
- `POST /api/orders/preview` — расчёт и проверка наличия без списания
- `POST /api/orders` — подтверждение: либо заказ `201`, либо `409`, если мест уже нет
- `POST /api/event/reset` — вернуть стенд в начало

## Что сознательно не делалось

- Оплата и платёжные данные.
- Письмо на email.
- База и постоянное хранение заказов.
- Удержание мест на время заполнения анкеты. Без него как раз возникает отказ «перед подтверждением».
